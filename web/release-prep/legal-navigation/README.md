## 신고·차단 서버 반영 차단점

이번 조회에서도 운영 마이그레이션 이력은 기존 7개이며, 추가할 두 스키마와 공개 함수 이름 6개가 없었다. 해당 이름과 일치하는 실행 중 작업도 관측되지 않았다. 이전 요청 시간대의 제한된 Postgres 로그에서는 중단 원인을 입증하는 오류를 찾지 못했다. 이것이 상위 API 요청의 완료·취소를 증명하지는 않는다.

이전 `apply_migration`은 실행 호스트가 교체돼 완료 응답을 회수하지 못했다. SQL 오류나 자동 승인 거절을 받은 것으로 기록하지 않는다. 실행 환경과 읽기 기능이 복구된 것만으로 같은 변경 요청을 다시 보내지 않았다. 원래 승인된 두 SQL의 내용·해시는 유지한다.

재개하려면 **이전 요청의 완료/취소 여부나 정상 변경 응답 경로를 확인할 새로운 근거**가 필요하다. 그 뒤 최신 이력·정확한 이름 충돌을 확인하고 승인된 첫 마이그레이션의 정상 결과를 받은 다음 두 번째를 진행한다. SQL 에디터 우회, `execute_sql` DDL, 이력 수동 삽입, 기존 VS 함수 덮어쓰기를 대안으로 사용하지 않는다. 이 사안은 사용자가 동일한 승인을 다시 주어야 하는 문제가 아니다.

근거: [제한된 읽기 진단 결과](migration-diagnosis.json), [진단 SQL 원문](diagnostic-queries.sql). SQL 파일은 조회 근거이며 운영 실행 요청이 아니다.
