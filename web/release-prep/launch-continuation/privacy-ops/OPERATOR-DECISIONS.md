# 운영자가 결정할 세 가지 — 실제 절차를 채택하기 위한 초안

**아래는 선택을 받기 위한 제안이며 아직 시행하지 않는다.** 실제 담당, 응답 목표, 보관기간은 선택 전까지 null이다. 회사·대표·기존 이메일·18세 이상 대상 여부는 다시 묻지 않는다. 공개 정책과 앱의 약속을 바꾸는 작업도 아직 실행하지 않는다.

## 1. 문의를 실제로 처리할 사람

**추천 A — 박지민 직접 담당**

기존 jmpark0611@gmail.com으로 들어오는 개인정보·삭제·신고 문의를 대표 박지민이 확인하고 처리 결정한다. AI는 최소정보 분류표·답변 초안을 준비하되 자동 발송·삭제를 하지 않는다. 기술 변경이 필요한 건은 구체적인 대상·범위를 검토한 후 실행한다.

**대안 B — 별도 담당자를 지정**

대표는 운영 책임을 두고, 실제 메일 확인·기한 관리·회신 담당자 1명을 별도로 지정한다. 지정 시 필요한 것은 담당자의 업무상 이름/연락 경로와 접근 권한이다. 사람을 정하기 전에는 위임이 완료됐다고 표시하지 않는다.

이 선택은 **문의 처리 담당 배정**이다. 법정 개인정보 보호책임자라는 직위를 자동 부여하거나 확인한 것으로 처리하지 않는다. 공개본의 책임자 표기는 실제 지정 사실에 맞춰 반영한다.

## 2. 최초 응답 목표

**추천 A — 1영업일 이내 접수·분류 안내를 목표로 운영**

내용을 읽고 지원번호와 필요한 최소 추가정보, 현재 확인 가능한 다음 단계를 먼저 답한다. 모든 데이터의 삭제 완료를 1일 안에 약속하는 뜻은 아니다.

**대안 B — 2영업일 이내 접수·분류 안내를 목표로 운영**

담당 가능 시간을 고려하여 초기 답변 목표를 더 길게 둔다. 권리 요청·긴급 노출 신고의 실제 우선순위 및 적용 법정기한은 별도로 관리한다.

두 안 모두 **미승인 내부 운영 목표**다. 영업일·휴일 기준과 담당 가능한 시간대를 채택 시 함께 적는다. 법정 조치·통지 기한을 이 숫자로 바꾸거나 자동 연장하지 않는다. 현재 확정 SLA는 없다.

## 3. 처리 종료 후 최소 처리표의 보관

두 안 모두 문의 원문·민감 첨부는 처리 및 실제 필요한 후속 목적이 끝나 불필요해지면 정리한다. 최소 처리표는 지원번호, 접수/처리일, 종류, 승인된 범위, 처리 여부, 결과 통지 여부 정도로 제한하고 원문·토큰을 복제하지 않는다.

**추천 A — 최소 처리표 30일 후 정리**

종료 후 재문의·처리 누락 확인을 위한 짧은 기간을 제안한다. 실제 목적·필요성을 확인하고 채택·고지한 뒤 적용한다.

**대안 B — 최소 처리표 90일 후 정리**

담당자가 재문의 확인을 더 오래 해야 하는 구체적 운영 사유가 있을 때 선택한다. 더 긴 보관의 필요성을 설명할 수 있어야 한다.

30일·90일은 **법에서 모든 문의에 정한 보관기간이 아니다.** 이번 제안만으로 채택되지 않는다. 별도 법정 보존이나 실제 분쟁 대응이 필요한 항목은 근거·대상·기간을 따로 기록하며, 일률적 “5년 보관”을 넣지 않는다. 삭제 요청을 선택한 기간만으로 자동 거절하지 않는다.

## 이 세 선택에 포함되지 않는 것

- 기존 bc_delete_account 또는 Auth 사용자 전체 삭제 실행 승인
- 새 인증된 지원 요청 기능이 이미 구현됐다는 선언
- 본인 확인이 안 된 이메일 요청의 임의 삭제·개인정보 제공
- 신고 서버 적용·자동 신고 검토·24시간 대응 완료
- Play의 계정 삭제 의무 면제 또는 필수 여부에 대한 추정
- 공개 정책 확정·배포·이메일 발송

위 항목은 기술적으로 확인한 범위와 실제 승인 절차에 따라 처리한다. 현재 앱에서 가능한 본인 결정 삭제와 기기 정보 정리는 바로 안내할 수 있다. 일반적인 수동 전체 삭제는 인증된 요청 근거·범위 검토가 준비되어야 한다.

## 기록할 선택값

- 문의 처리 담당: 선택 전
- 최초 응답 목표: 선택 전
- 최소 처리표 보관기간: 선택 전
- 선택 확인일·적용 시작일: 미지정

지금 사용자에게 세 질문을 발송하지 않았다. 이 문서와 완성한 처리 절차·답변을 검토한 뒤 필요한 선택만 한 번에 받는다.
